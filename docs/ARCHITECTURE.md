# 开发架构

项目使用分层经典脚本：`history.js` 提供知识，`review.js` 补充专题分析与对比，`questions.js` 提供原创题，`core.js` 提供可测试纯函数，`app.js` 负责交互。页面没有打包步骤，也没有 `fetch()` 数据依赖，因此可在本地文件协议下启动。事件ID显式保存，用户笔记关联不依赖数据行号。

1.2.0加入 `exams.js` 作为独立的题号—知识点索引层。索引只有项目编写的主题摘要、小问关联及出处，没有题干和标准答案，不进入QUESTION_BANK。`#exams` 页面与时间轴通过eventIds双向跳转，纯函数筛选支持年份、题型、阶段、节点、范围和关键词。导入题库的sourceUrl为可选字段，校验后才会生成可点击链接；旧备份不需要迁移。

使用哈希路由：`#timeline`、`#practice`、`#mistakes`、`#memory`、`#progress`、`#about`。哈希值只从白名单选择页面，不插入HTML。时间轴筛选、练习会话及草稿留在内存，长期学习状态写入LocalStorage。页面重载会重置筛选和未完成练习，已经提交的答题记录保留。

动态页面以事件委托监听点击、输入与选择变化，笔记输入只保存状态而不重建textarea，防止光标跳动。搜索只刷新时间轴与详情，不替换搜索输入。缩放只改变节点宽度并锚定当前视窗。普通触屏滑动由浏览器原生滚动处理，双指距离变化用于缩放。

所有题目通过 `eventIds` 绑定事件，由界面计算反向关联。一个题可属于多个节点，章节筛选按任一关联节点匹配。题库导入先完整校验并检测全局ID冲突，再执行追加；备份先验证完整状态，再整体替换，恢复时清除旧练习会话。

存档损坏时不会自动覆盖原值。出现跨标签存储事件时当前标签切换到存档保护模式；用户可先导出临时记录后刷新。存储写入失败会在页面顶部保留错误提示；所谓“保存成功”只在实际setItem成功后出现。

`sw.js` 使用版本化静态缓存，安装时完整缓存应用文件，运行时优先读取当前版本缓存。请求仅处理同源静态应用资源；外部参考链接不被缓存。每次发布修改缓存名，新worker完成安装后接管，下次刷新加载新资源；不能只改数据而保留旧缓存版本名。整体安装避免逐文件网络更新导致数据结构混用，未来可进一步采用资源指纹。

扩展时优先保持数据与渲染分离。新增复杂业务可拆分app.js为多文件经典脚本；若改为ES模块，需重新考虑file://直接打开的限制。更改持久化结构需加入迁移及恢复兼容测试。当前不包含后端、云同步、AI评分或完整真题分发服务。
